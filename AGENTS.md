# AGENTS.md

Инструкция для ИИ-ассистентов (Claude Code, Cursor, Codex, Copilot и т. п.),
работающих с этим репозиторием. Люди-разработчики — тоже целевая аудитория.

## Границы

Этот проект — **публичный анализ** Reels в Instagram. Что можно и чего нельзя
делать с данными, определено в ТЗ и техспеке. Для ассистента границы такие:

- **Не писать код обхода защиты Instagram от ботов.** Сюда входит: подмена
  браузерных отпечатков, имитация устройств и человеческого поведения,
  решение капч, вход через чужие или купленные аккаунты, ротация «личностей»
  для обхода банов. При запросе — объяснить, что это обход, и предложить
  законные пути: Graph API или платный провайдер данных.
- **Не хранить в коммитах секреты и персональные данные.** `.env` в `.gitignore`.
  Отчёты импорта с ФИО и кураторами (`docs/import_report.md`) — тоже.
- **Прежде чем запускать сетевые запросы к Instagram, Meta или сторонним
  сервисам,** предупредить человека и дождаться подтверждения. В тестах
  любые внешние вызовы заменяются на `httpx.MockTransport`.

## Правила кода

- **Python 3.12, строгие типы.** `mypy --strict` должен проходить. Для
  необязательных полей — `| None`, не `Optional`.
- **`ruff` чистый.** Форматирование и проверки — `uv run ruff format` и
  `uv run ruff check --fix`. Исключения для длинных SQL — в `pyproject.toml`.
- **Чистые функции разбора.** `parser/parse/*` не знает ни про сеть, ни про
  базу. Обязательное поле не найдено → `InvalidResponse`. Необязательное →
  `None`, никогда не 0 и не пустая строка.
- **Идемпотентность.** Любая задача выполняется повторно без побочных
  эффектов: upsert по `user_pk` / `media_pk`, один снимок на ролик в сутки.
- **Один путь для каждого ответа:** `сырой → S3 + raw_response → classify →
  parse → validate → store`. Невалидный ответ ничего не пишет в базу.
- **Миграции Alembic — только обратно совместимые.** Автогенерация пропускает
  партиции `metric_snapshot_YYYY_MM` (см. `infra/migrations/env.py`).
- **Фронтенд.** React 19 + TypeScript, TanStack Query, ECharts. Цвета графиков
  берутся из CSS-переменных, тёмная тема — те же токены. Фильтры живут в
  адресе страницы (`useParam`).

## Полезные команды

```bash
make check               # ruff + mypy + pytest; стандартная проверка
make up                  # Postgres, Redis, S3 на localhost
make migrate             # alembic upgrade head
uv run pytest -q tests/unit            # только юниты, без Postgres
uv run pytest -q tests/integration     # интеграционные, нужен make up

uv run smart-parser meta-check         # Graph API: токен, права, один запрос
uv run smart-parser work --once        # опустошить очередь и выйти
uv run smart-parser recompute          # пересчёт всплесков и статистики
```

## Отладка парсера

- Все ответы Instagram / Graph API сохраняются в S3 (`raw/{yyyy-mm-dd}/{task_id}/`)
  и в таблице `raw_response` с отпечатком структуры (`shape_fingerprint`).
- После починки разбора: `uv run smart-parser reparse` (ещё не реализовано —
  запланировано).
- Экран «Парсер» в интерфейсе показывает очередь, упавшие задачи, карантин
  метрик и невалидные ответы с ошибками разбора.

- Короткие осмысленные сообщения на английском, по теме.

  (Claude Code и подобные).
- Не коммитить `.env`, `docs/import_report.md`, скачанные `poc_out/`,
  логи и временные файлы.

## Если застряли

Не придумывайте поля ответов Instagram «по памяти» — проверяйте в сохранённом
`raw_response` или по документации Meta. Если формат изменился, добавьте
образец в `tests/fixtures/responses/` и опишите изменение.
