# smart-parser

Внутренняя система анализа Reels в Instagram: ведёт списки брендов и их
креаторов, собирает публикации, находит аномально успешные ролики («всплески»)
и показывает всё это на удобных экранах с таблицами, графиками и сравнением
нашего бренда с конкурентами.

Основание — «ТЗ: данные Instagram, креаторы и аномалии» (05.10.2026) и
«Техническая спецификация: дашборд анализа конкурентов» (02.10.2026).
План работ по сессиям — [docs/PLAN.md](docs/PLAN.md). Что происходит
дальше — [docs/ROADMAP.md](docs/ROADMAP.md).

## Что уже работает

- **База, миграции, Docker Compose.** Postgres 16 с партициями снимков по
  месяцам, Redis, S3-совместимое хранилище. С нуля поднимается командой `make up`.
- **Два источника данных.** Официальный Instagram Graph API (Business Discovery) —
  основной путь без блокировок (см. [docs/META_SETUP.md](docs/META_SETUP.md)).
  Свой веб-источник без логина (`SP_SOURCE=web`) — для случаев, когда Instagram
  отдаёт данные публично и запрещено ТЗ только обходить защиту; работает в
  бережном темпе с одной sticky-сессией прокси на задачу.
- **Конвейер сбора.** Задача → сырой ответ → разбор → проверка → запись.
  `profile`, `feed_head`, `feed_deep`, `backfill` (с продолжением с курсора),
  `manual_refresh`, `brand_tagged`, `candidate_probe`. Невалидный ответ ничего
  не пишет в базу, блокировка откладывает задачу, воркер останавливается после
  3 блокировок подряд.
- **Разбор ответов** — ~30 полей профиля и ролика, включая просмотры в Instagram
  и Facebook, аудио (свой или трендовый, исполнитель), геометка, партнёрство,
  ремиксы.
- **Сигналы из подписи** — хэштеги с кириллицей, упоминания, артикулы WB,
  подменные WW-коды, промокоды, отметки и соавторы.
- **Поиск креаторов брендов** — доказательства по шести осям (партнёрство,
  collab, отметки, артикул, маски ников, бренд в шапке профиля); уровень
  уверенности `confirmed / likely / possible`.
- **Расчёт всплесков** — медиана 20 предыдущих роликов автора на том же
  возрасте; поправка на возраст; категории `high / strong / viral`;
  обязательный проверочный пример ×13,3 как юнит-тест.
- **Ночной пересчёт** — связи ролик–бренд, подневные просмотры (без фальшивых
  всплесков у роликов из истории), ~40 показателей на креатора.
- **Веб-интерфейс.** Шесть экранов: обзор, креаторы, аномалии, бренды,
  кандидаты, парсер, «что работает». CSV-выгрузки, фильтры в адресе страницы.

Около 160 тестов, `ruff` и `mypy --strict` чистые.

## Структура

| Каталог | Что внутри |
|---|---|
| `parser/parse` | чистые функции raw JSON → `IgProfile` / `IgMedia` / `IgMetrics` |
| `parser/signals` | хэштеги, упоминания, артикулы WB, WW-коды, промокоды |
| `parser/validate` | проверки метрик перед записью: `metric_drop`, карантин, нули |
| `parser/raw` | отпечаток структуры ответа, хранение сырых ответов в S3 |
| `parser/sources` | интерфейс, `WebSource` (без логина), `GraphApiSource` (Meta API) |
| `parser/queue` | очередь на `scrape_task`: приоритеты, идемпотентность, аренда |
| `parser/store` | upsert профилей, роликов, снимков, сигналов |
| `parser/pipeline.py` | конвейер задачи целиком |
| `parser/worker.py`, `planner.py` | воркер и расписание суточного цикла |
| `parser/importers` | импорт списков брендов и креаторов из таблицы заказчика |
| `core/db` | модели SQLAlchemy (схема БД) |
| `core/metrics` | всплески, подневные просмотры, статистика креатора |
| `core/discovery` | доказательства и уверенность связи креатора с брендом |
| `api` | FastAPI для веб-интерфейса |
| `web` | интерфейс на React (Vite, TanStack Query, ECharts) |
| `infra` | Docker Compose, миграции Alembic |
| `tests` | юнит- и интеграционные тесты |

## Запуск с нуля

Нужны Docker и [uv](https://docs.astral.sh/uv/).

```bash
cp .env.example .env     # заполните SP_META_* по docs/META_SETUP.md
uv sync
make up                  # Postgres 16, Redis, S3 (SeaweedFS) на localhost
make migrate             # alembic upgrade head
make check               # ruff, mypy --strict, pytest
```

## Веб-интерфейс

```bash
make demo    # демо-данные: 4 бренда, ~40 вымышленных аккаунтов demo_*, стирает базу!
make api     # http://localhost:8000/api/docs
make web     # http://localhost:5173
```

| Парсер | покрытие, очередь, упавшие задачи, карантин метрик |

## Сбор данных

**Источник Graph API (бесплатно, без блокировок) —** [docs/META_SETUP.md](docs/META_SETUP.md).

```bash
uv run smart-parser work          # воркер: выполняет задачи из очереди
uv run smart-parser plan night    # 01:00 МСК: profile + feed_head всех аккаунтов
uv run smart-parser plan day      # 14:00: первая страница ленты
uv run smart-parser plan tagged   # 10:00: brand_tagged (только для web-источника)
uv run smart-parser recompute     # после цикла: всплески и статистика
```

Расписание на macOS — `scripts/macos/install-schedule.sh`.

## Импорт списков

```bash
uv run smart-parser import-lists path/to/lists.xlsx --dry-run
uv run smart-parser import-lists path/to/lists.xlsx          # запись в базу
```

Из таблицы берутся бренды, их аккаунты, креаторы, окончания ников креаторов
бренда и артикулы WB (из листов статистики). Отчёт с проблемами в данных —
`docs/import_report.md` (не коммитится, содержит персональные данные).

## Принципы (техспека §2)

Сначала сырой ответ, потом разбор. Непонятный ответ — ошибка, а не мусор в
базе. Необязательное поле — `null`, никогда не 0. Идемпотентность: upsert по
`user_pk` / `media_pk`, один снимок на ролик в сутки. Только публичные данные
без логина. **Стена логина, капча и бот-проверка не обходятся.**
