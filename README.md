# smart-parser

Парсер Instagram Reels для дашборда анализа конкурентов: сбор профилей и
роликов брендов и их креаторов, автопоиск креаторов бренда, расчёт всплесков
(аномалий) и выгрузки для сравнения. Без интерфейса и API.

Основание — «ТЗ: данные Instagram, креаторы и аномалии» (05.10.2026) и
«Техническая спецификация: дашборд анализа конкурентов» (02.10.2026).
План работ — [docs/PLAN.md](docs/PLAN.md).

## Структура

| Каталог | Что внутри |
|---|---|
| `parser/parse` | чистые функции raw JSON → `IgProfile` / `IgMedia` / `IgMetrics`, классификация блокировок |
| `parser/signals` | хэштеги, упоминания, артикулы WB, отметки / collab / партнёрство |
| `parser/validate` | проверки метрик перед записью: metric_drop, карантин, нулевые просмотры |
| `parser/raw` | отпечаток структуры ответа, хранение сырых ответов в S3 |
| `parser/sources` | `InstagramSource`, `WebSource` (публичные веб-запросы без логина) |
| `parser/queue` | очередь на `scrape_task`: приоритеты, идемпотентность, аренда, курсор, повторы |
| `parser/store` | upsert профилей, роликов, снимков, сигналов |
| `parser/poc.py` | PoC этапа 1: что отдаётся без логина и на какую глубину |
| `core/db` | модели SQLAlchemy (схема БД) |
| `core/metrics` | расчёт всплесков и ночной пересчёт media_stats / media_brand |
| `core/discovery` | доказательства и уверенность связи креатора с брендом |
| `api` | FastAPI для веб-интерфейса |
| `web` | интерфейс на React |
| `infra` | Docker Compose, миграции Alembic |

## Запуск с нуля

Нужны Docker и [uv](https://docs.astral.sh/uv/).

```bash
cp .env.example .env
uv sync
make up        # Postgres 16, Redis, S3 (SeaweedFS) на localhost
make migrate   # alembic upgrade head
make check     # ruff, mypy --strict, pytest (включая интеграционные на Postgres)
```

## Веб-интерфейс

Внутренняя консоль: FastAPI (`api/`) + React 19, Vite, TanStack Query, ECharts (`web/`).

```bash
make demo   # демо-данные: 4 бренда, ~40 вымышленных аккаунтов demo_*, ~1 150 роликов (стирает базу!)
make api    # http://localhost:8000/api/docs — документация API
make web    # http://localhost:5173 — интерфейс
```

| Экран | Что делает |
|---|---|
| Обзор | наш бренд против конкурентов: доля всплесков, viral, медианы, динамика по неделям, топ всплесков |
| Аномалии | все всплески с фильтрами (период, бренды, чьи, порог ×2/×5/×10), карточки или таблица, выгрузка CSV |
| Бренды и креаторы | список брендов, добавление, импорт CSV; страница бренда — рейтинг креаторов, добавление по нику, пороги |
| Кандидаты | найденные системой креаторы с доказательствами и уверенностью, «Добавить» / «Скрыть» |
| Креатор | KPI, график просмотров роликов, сетка роликов со всплесками, ручное обновление |
| Парсер | покрытие, очередь по приоритетам, упавшие задачи, карантин метрик, невалидные ответы |

Фильтры хранятся в адресе страницы — ссылку можно переслать. Обложек пока нет (появятся
после задачи media_cover), вместо них цветная плашка; клик открывает ролик в Instagram.

## PoC

Файл с аккаунтами — по одному нику или ссылке на строку. Без прокси запросы
идут с текущего IP; для нагрузочного прогона задайте `SP_PROXY_URL` в `.env`.

```bash
uv run smart-parser poc --accounts accounts.txt --brand-query waistline
```

Все ответы сохраняются как есть в `poc_out/raw/` (из них собирается
библиотека образцов для тестов), отчёт — в `poc_out/poc_report.md`. Стену
логина, капчу и 429 парсер не обходит: аккаунт останавливается, после трёх
блокировок подряд — весь прогон.

## Принципы (техспека §2)

Сначала сырой ответ, потом разбор. Непонятный ответ — ошибка, а не мусор в
базе. Необязательное поле — `null`, никогда не 0. Идемпотентность: upsert по
`user_pk` / `media_pk`, один снимок на ролик в сутки. Только публичные
данные без логина.
