# План работ

Объём — «ТЗ: данные Instagram, креаторы и аномалии» (05.10.2026): парсер, поиск
креаторов, расчёт аномалий и выгрузки. Без интерфейса, API и разметки роликов.
Как делаем — «Техническая спецификация» (02.10.2026), разделы 2–9 и 13.

## Сессия 1 (5 часов) — этап 1 «PoC и основа» + начало этапа 2

Принцип порядка: сначала то, что не зависит от сети и Instagram (чистые
функции, схема БД, расчёты), — это можно довести до тестов сразу. Всё, что
требует реальных ответов Instagram, готовим так, чтобы PoC можно было
запустить одной командой, как только появятся прокси.

| Час | Блок | Результат (критерий «готово») |
|-----|------|-------------------------------|
| 1 | Каркас monorepo | `parser/`, `core/`, `infra/`, `pyproject` (uv, Python 3.12), ruff + mypy --strict + pytest, Docker Compose (Postgres 16, Redis, MinIO), GitHub Actions CI, README. `make check` зелёный |
| 1 | Схема БД | SQLAlchemy-модели и первая миграция Alembic со всеми таблицами ТЗ (brand, account, account_username_history, account_snapshot, brand_account, media, metric_snapshot с партициями, metric_quarantine, media_signal, media_stats, media_brand, scrape_task, raw_response). `alembic upgrade head` с нуля на чистой базе |
| 2 | Модели и разбор | pydantic `IgProfile`, `IgMedia`, `IgMetrics`; чистые функции raw JSON → модель; обязательное поле не найдено → `InvalidResponse`, необязательное → `null`, не 0 (Ф-8) |
| 2 | Сигналы из подписи | хэштеги (с кириллицей), упоминания, артикулы WB с уверенностью; структурные сигналы (usertags, coauthors, sponsors) (Ф-10). Тесты на примерах из спеки |
| 3 | Проверки метрик | metric_drop ≤ 5%, карантин > 5% и рост ×1000, play_count = 0 у ролика старше 1 ч (Ф-9) — чистые функции + тесты |
| 3 | Расчёт всплесков | `core/metrics`: всплеск по возрасту, insufficient_data < 8, метод current_views, категории и пороги бренда (Ф-21). **Обязательный тест ×13,3 viral** |
| 3 | Уверенность креатора | веса сигналов, `min(1, Σ/100)`, уровни Confirmed/Likely/Possible, правило возврата hidden (Ф-19) — чистые функции + тесты |
| 4 | Сырые ответы и WebSource | отпечаток структуры (хэш множества путей ключей), ключ S3 `raw/{yyyy-mm-dd}/{task_id}/{page}.json.gz`, запись в MinIO; `InstagramSource` (интерфейс) + `WebSource` (публичные веб-эндпоинты, один набор заголовков из конфига, без логина); распознавание 429 / стены логина / 404 |
| 4 | Скрипт PoC | `smart-parser poc --accounts accounts.txt`: профиль + лента Reels с пагинацией, все ответы в S3 и в `tests/fixtures`, отчёт: есть ли play_count, глубина пагинации, доля успешных запросов, трафик |
| 5 | Хранилище и очередь (основа) | upsert профиля/ролика/снимка по user_pk/media_pk, `scrape_task` с ключом идемпотентности, аренда, курсор; CLI: импорт брендов из CSV, `refresh <username>` |
| 5 | Итог сессии | прогон всех тестов, smoke на docker compose, обновление этого плана и списка открытых вопросов |

Что **не** успеем в сессии 1 и делаем дальше: планировщик по расписанию
(arq), лимиты / прокси / предохранитель, канарейка, Prometheus, Telegram,
сервер-имитатор, brand_tagged и candidate_probe, выгрузки CSV.
