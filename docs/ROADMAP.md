# Что делаем дальше

Короткий план на ближайший этап. Крупные вехи — в [PLAN.md](PLAN.md).

## 0. Выбор источника данных (блокер)

С домашнего IP Instagram без логина не отвечает (229 на первый же запрос,
см. [poc_2026-10-11.md](poc_2026-10-11.md)). Обход защиты ТЗ запрещает.
Варианты:

1. **Graph API через ваш бизнес-аккаунт** — бесплатно, без блокировок,
   инструкция в [META_SETUP.md](META_SETUP.md). Нужен VPN с постоянным IP.
   У конкурентов не будет просмотров Reels (API их не отдаёт), всплески
   придётся считать по лайкам и комментариям — грубее, но стабильно.
2. **Платный провайдер** (HikerAPI, ScrapeCreators) — ~$10–40 в месяц,
   полные данные включая просмотры. Адаптер пишется за час.
3. **Свой веб-парсер с другого IP** — мобильный интернет, бесплатный VPS
   вне РФ. Работает, пока Instagram отдаёт данные без логина.

Пока источник не выбран и не настроен, сбор не идёт. Код готов для всех трёх.

## 1. Настройка Graph API — рекомендуемый путь

Шаги в [META_SETUP.md](META_SETUP.md). После него:

- `uv run smart-parser meta-check --username waistline_shop` — проверка;
- `uv run smart-parser import-lists path/to/lists.xlsx` — списки заказчика;
- `uv run smart-parser work --once` — первый сбор (~164 запроса);
- `uv run smart-parser recompute` — всплески и статистика;
- `scripts/macos/install-schedule.sh` — расписание на Mac.

## 2. Что доделать в парсере

- **`reparse`** — пересборка данных из сырых ответов без сети после починки
  разбора (техспека §3, §7).
- **Канарейка** — профиль + первая страница ленты контрольного аккаунта
  каждые 30 мин с полной проверкой схемы (§7).
- **Prometheus и Telegram-алерты.** Метрики — в коде (`circuit_breaker_open`,
  `queue_depth` и т. д.), остался экспорт и отправка алертов.
- **Сервер-имитатор** для интеграционных тестов в CI с таймаутами, 429,
  сломанным курсором (§7).
- **`media_cover`** — копии обложек в S3, пока CDN-ссылка жива (§4).
- **HTTP-слой:** token bucket в Redis на процесс запросов, адаптация темпа
  при 429 (×0,5, восстановление +10% за 15 мин), счётчик ошибок на IP.

## 3. Что доделать в интерфейсе

- **Экран «Наш бренд»** отдельно — текущий «Обзор» показывает всех.
- **Карточка аккаунта в карточке ролика** при наведении — быстрый просмотр
  профилей автора без перехода.
- **Экран «База роликов»** — таблица со всеми роликами и фильтрами, выгрузка
  CSV (§11, v1.1).
- **Экран связок** — лифт комбинаций тегов (§12, v1.1).

## 4. v1.1 — разметка роликов

Что собирает парсер уже сейчас, чтобы потом ответить на вопрос «почему
залетело»: подпись, звук, длительность, обложка, ссылка на видео, отметки,
collab, партнёрство. Сам разбор — отдельный блок работ:

- скачивание видео (ссылка живёт несколько часов);
- транскрипция (OpenAI Whisper локально) и OCR первых кадров (tesseract);
- LLM-разметка: формат, хук, механика, товар (JSON-схема);
- экран «Тренды / Связки» в интерфейсе.

## 5. v1.2 — расширенный поиск креаторов

- `candidate_probe` работает в коде; остаётся калибровка весов по известному
  списку наших креаторов (≥ 80% Confirmed / Likely).
- MPSTATS: артикул → продавец → бренд, кэш 30 дней; продажи ±14 дней вокруг
  всплеска (техспека §13).

## 6. Деплой

- Сервер вне РФ (бесплатный Oracle Cloud Always Free или ~500 ₽/мес VPS).
- Docker-образы, боевой `docker-compose`, `deploy.sh`.
- Бэкапы Postgres в S3 другого региона, проверка восстановления раз в месяц.
- Доступ коллегам — через Tailscale или SSH-туннель.

## 7. Приёмка (техспека §7, §8)

- 14 дней SLO на боевых данных подряд.
- Ручная сверка 50 роликов, расхождение ≤ 2%.
- Три учения: падение воркера, блокировки, изменение формата Instagram.
- Runbook: «Изменился формат», «Блокировки», «Переключение на резерв»,
  «Пересборка данных».
